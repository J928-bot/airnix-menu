# AIRNIX 個別メニュー（LINEミニアプリ）

用賀店モニターのシステム化。お客様がLINEの中で報告 → AI（Claude）が次回メニューを作成 → 記録 → スタッフの声掛けリスト。

## 流れ（宮内さんの指示：目標設定 → 目標に向けたメニュー → 進捗管理）
1. **目標**：来店時にスタッフと本人で決める（体重・ウエスト＋期日。2026-09-29 ジェイさん決定：指標は体重・ウエスト）
2. **メニュー**：歩くメニュー（AI）＋筋トレメニュー（スタジオ・自重・段階1〜5）＋食事（あすけんのカロリーを入力）
3. **進捗**：スタッフが来店直後・運動前に測定 → お客様画面に目標線つきのグラフ

## できること
- **お客様（/）**：LINEで開くだけでログイン。目標と進捗グラフ、歩く／筋トレのメニューを見る → トレーニング後に報告 → 次回メニューがその場で表示される。食事は1日の摂取カロリーとあすけんの目標カロリーを入力
- **筋トレメニュー**：自重（スクワット・ヒップリフト・膝つき腕立て・プランク等）の固定テンプレート5段階。報告に応じて1段階ずつ上下（AIは使わない）。**種目と回数は試案なので、公開前にスタッフ・宮内さんの確認が必要**
- **安全停止**：「痛みや体調の変化：あり」ならメニューを作らず「要確認」に回す（スタッフが確認して再開）
- **AIのメニュー作成**：モニターAI（仕様書v4.27）のルールで作成。合計30分・動作名・抵抗などの検証に通らない答えは使わず、簡易ルールで作る
- **スタッフ（/staff.html）**：全員の状態（要確認／登録待ち／測定時期／最終回前／来店なし／筋トレ未実施／食事未入力／継続中／終了）と声掛けの内容、目標に対する進捗、直近7日の食事、直近3回の記録。登録（目標＋初回メニュー）と測定の記録。登録時に身長・性別を入れると目標の目安（BMI・標準体重・ウエスト85/90cm・3か月で体重3%減／ウエスト2cm減）と無理な目標への注意が出る。「目標を見直す」で回数・メニューを保ったまま目標だけ変更
- 最終回の報告で「終了」になり、スタッフ画面に「終了測定・ダブル枠とスタジオの案内」が出る

## 構成
- 画面：`public/`（LIFF SDK）
- サーバー：Cloudflare Pages Functions（`functions/api/`）＋共通処理 `src/lib.ts`
- 保存先：Cloudflare D1（`schema.sql`）
- AI：Anthropic API（`claude-opus-5`。拒否時は `fallbacks: "default"` で自動的に別モデルで再実行）

## 公開までの手順
1. **Node.js を入れる**（このMacには未インストール）
2. **Cloudflare アカウント**を作成（無料枠で足りる見込み）
3. `npm install` → `npx wrangler login`
4. D1を作る：`npx wrangler d1 create airnix-menu` → 表示された `database_id` を `wrangler.toml` に貼る → `npm run db:init`
5. **LINE Developers**：用賀の公式アカウント（@430tauan）と同じプロバイダーで「LINEミニアプリ」チャネルを作成
   - エンドポイントURL：Cloudflare Pagesの公開URL（例 `https://airnix-menu.pages.dev/`）
   - スコープ：`openid`, `profile`
   - 控えるもの：**チャネルID** → `wrangler.toml` の `LINE_CHANNEL_ID`／**LIFF ID** → `public/common.js` の `LIFF_ID`
6. AIのキーを登録：`npx wrangler pages secret put ANTHROPIC_API_KEY`
7. 公開：`npm run deploy`
8. スタッフのLINEユーザーIDを `STAFF_USER_IDS` に入れて再公開（スタッフが一度ミニアプリを開くと、D1の `members` に userId が残るので、そこから拾える）
9. 公式LINEのリッチメニューに「個別メニュー」ボタン（ミニアプリのURL）を追加。スタッフは同じURLの `/staff.html`

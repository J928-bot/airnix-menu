# AIRNIX 個別メニュー（Web版）

お客様がAirNixアプリのリンクから開く「個別メニュー」の画面と、スタッフ用の画面です。
2026-10-18 時点：**未公開**（公開前に決めることは最後の章）。

---

## 1. 店長向け：これは何をするものか

- **お客様**：AirNixアプリのリンクから開く → スタッフが渡した「マイコード」（8文字）を入れる → プライバシーポリシーに同意 → 今日のトレッドミルのメニュー、次の来店までのNTC、あすけんの記録日数、目標までの推移、効果レポートが見られる。終わったら「楽だった／ちょうど／きつかった」と痛み・体調の変化を報告すると、次回のメニューが自動で変わる。
- **スタッフ**：`/staff.html` を開き、名前と店舗の合言葉でログイン。上から「すぐ対応 → 気にかける → 案内のタイミング」の順に並ぶ。新規登録、体重・ウエストの測定、体調確認、マイコードの作り直し、利用終了、削除ができる。
- 一度ログインしたお客様は、**最後に開いてから180日**はコードを入れ直さずに開けます（同じスマホ・同じアプリの場合）。スタッフは12時間でログインが切れます。
- 料金は画面に書いていません（料金は hacomono・料金表で確認して案内する）。

## 2. 仕組み（こうやさん・エンジニア向け）

| 部分 | 中身 |
|---|---|
| 画面 | `public/`（素のHTML/CSS/JS。ビルド不要）。`index.html`＝お客様、`staff.html`＝スタッフ、`privacy.html`＝ポリシー |
| サーバー | Cloudflare Pages Functions（`functions/api/*.ts`）。共通処理は `functions/api/_middleware.ts` |
| データ | Cloudflare D1（SQLite）。表の定義は `schema.sql` |
| 決まり | `src/logic.ts`（トレッドミル段階①〜④・NTC・来店集計。外部に依存しない純粋な関数）、`src/summary.ts`（効果レポート・スタッフ向けの注意）、`src/lib.ts`（ログイン・Cookie・試行回数制限・操作記録） |
| テスト | `test/logic.test.ts`（`npm test`） |

API（すべて `/api/` 配下・JSON）

| パス | 用途 |
|---|---|
| `POST /api/login` `{code}` | マイコードでログイン（Cookie `am_m` を発行） |
| `POST /api/logout` | ログアウト |
| `POST /api/consent` `{agree:true}` | プライバシーポリシーへの同意 |
| `GET /api/me` | お客様の画面に出す内容一式 |
| `POST /api/report` | 来店時の報告（トレッドミル・NTC・痛み） |
| `POST /api/asken` `{days}` | 今週あすけんで記録した日数 |
| `POST /api/staff/login` / `DELETE` | スタッフのログイン／ログアウト（Cookie `am_s`） |
| `GET /api/staff/members[?archived=1]` | スタッフの一覧 |
| `POST /api/staff/members` `{action,...}` | create / edit / measure / resolve / track / upsell / reissue / archive / restore / delete |

メニューが自動で変わる決まり（`src/logic.ts`・2026-10-18 店長決定。スタッフはメニュー作りに関わらない）

- トレッドミル：楽→1つ上げる／ちょうど→そのまま／きつい・痛み→1つ戻す（段階①〜④ → きつめの抵抗+1 → 早歩き+0.2km/h）。速さの上限は一律に決めず、ご本人の報告で決まる。安全上限だけ：早歩き12.0km/h、抵抗のないマシン（D〜G）のきつめ14.0km/h、抵抗6
- 来店は**日ごと**に数える（プレミアムの同じ日の2回目は、報告は残すが日数は進めない）。最初の4日は、きつめの区間を入れない
- 間があいたら：14日以上で1つ軽く、28日以上で段階①から（来店日数も0に戻し、最初の4日の決まりをもう一度）
- ゆっくりの速さは早歩きと重ならない（ゆっくりの上限＝早歩きの0.1km/h下まで）
- NTC：プログラムを実施率70%以上で終えたら次へ。目的の最後のプログラムを終えたら、次の目的へ自動で進む（基本→走る・競技→体のケア→基本。「忙しい」は終えたら基本の2本目へ。1本目の「基礎から」は済んでいるため）。お客様には報告後のメッセージで知らせる。スタッフが目的を変えることもできるが、必須ではない

## 3. 公開の手順（Node.js が入ったPCで、担当者が行う）

1. Cloudflare のアカウントを作る（無料プランで動きます。※下の「無料プランの上限」参照）
2. このフォルダで `npm install`
3. `npx wrangler login`
4. データベースを作る：`npx wrangler d1 create airnix-menu` → 表示された `database_id` を `wrangler.toml` に貼る
5. 表を作る：`npm run db:remote`
6. Pagesのプロジェクトを作る：`npx wrangler pages project create airnix-menu`
7. スタッフの合言葉を設定（10文字以上・コードには書かない）：`npx wrangler pages secret put STAFF_PASSWORD`
8. 型とテストの確認：`npm run check` と `npm test`（**2026-10-18時点では Node が無いため未実行**）
9. 公開：`npm run deploy` → `https://airnix-menu.pages.dev` で開けるようになる
10. 独自ドメイン（例 `menu.airnix.co`）：Cloudflareの画面 → Workers & Pages → airnix-menu → Custom domains で追加
11. 公開後の確認：スタッフ画面で自分を登録 → 出たコードでお客様画面に入る → 報告 → スタッフ画面に反映されるか

ローカルで試すとき：`.dev.vars` に `STAFF_PASSWORD=...` を書き、`npm run db:local` → `npm run dev`（http://localhost:8788）。

無料プランの上限（目安）：Functions 1日10万回、D1 1日500万行の読み取り。スタッフの一覧は全員分を3回の問い合わせでまとめて読むため、人数が増えても1回の上限（無料50回）に当たりません。

## 4. AirNixアプリからのつなぎ方（こうやさんへ）

- アプリには **URLを1つ置くだけ**（例 `https://menu.airnix.co/`）。会員IDなどをURLに付ける必要はありません。
- **アプリ内のブラウザ（WebView）で開く場合**
  - ログイン状態は WebView の Cookie に保存されます。iOSの `WKWebView` は既定の `WKWebsiteDataStore.default()` を使えば、アプリを閉じても180日残ります（`nonPersistent()` にすると毎回マイコードが必要になるので使わないでください）。
  - `target="_blank"` のリンク（NTCで開く・あすけんを開く）は、WebViewが何もしないことがあります。`WKUIDelegate` の `createWebViewWith` か `decidePolicyFor` で、外部のURLは Safari（`UIApplication.shared.open`）で開くようにしてください。NTCのリンクはそのまま開けばNTCアプリに飛びます。
  - 確認の画面（ログアウト・痛みありの送信など）は、`confirm()` を使わず画面の中に出すようにしてあります（WebViewでは `confirm()` が出ないことがあるため）。
- **外部ブラウザ（Safari・Chrome）で開く場合**：ログインはそのブラウザに保存されます。アプリ内とSafariではCookieが別なので、どちらかに統一してください。**おすすめは「アプリ内のWebView」**（毎回同じ場所で開けるため）。
- スタッフがお客様のスマホで一緒にコードを入れるときは、`https://…/?c=XXXXXXXX` を開くと自動でログインし、アドレスからコードは消えます（コードを含むURLをLINE等で送るのは避けてください）。

## 5. 安全のための仕組み

- マイコードは**ハッシュだけ保存**（コードそのものはDBに残らない）。読み間違えやすい 0/O/1/I/L は使わない。約8,500億通り。
- ログインのCookieは `HttpOnly; Secure; SameSite=Lax`。DBにはトークンのハッシュだけを保存。
- 総当たり対策：お客様は同じ回線から15分に30回（店内Wi-Fiは全員が同じ回線のため多め）、スタッフは5回まで。IPv6は/64単位で数える。
- 他のサイトからの送信を断る（`Origin` の確認）。APIの応答はキャッシュさせない。
- `public/_headers`：CSP（外部のスクリプト・画像を読まない、インラインのスクリプト禁止）、iframe埋め込み禁止、HSTS、検索エンジンに載せない。
- 痛み・体調の情報は、**同意（POLICY_VERSION）を取ってから**でないと送れない。ポリシーを変えたら `src/lib.ts` の `POLICY_VERSION` を上げると、全員に再同意を求める。
- スタッフの操作（ログイン・登録・測定・コード作り直し・削除など）は `audit` 表に「誰が・いつ・何を」残る。削除したときは、記録の中のお名前も消す。
- 想定外のエラーは短い日本語だけ返し、中身はCloudflareのログ（`console.error`）に残す。

## 6. バックアップ

- D1 には **Time Travel**（過去の任意の時点に戻せる。無料プランは7日前まで、有料プランは30日前まで）が標準で付いています。
  - 確認：`npx wrangler d1 time-travel info airnix-menu`
  - 戻す：`npx wrangler d1 time-travel restore airnix-menu --timestamp=2026-11-01T09:00:00+09:00`（**全体が戻るので、実行前に店長に確認**）
- 月に1回、手元にも保存：`npx wrangler d1 export airnix-menu --remote --output=backup-YYYYMMDD.sql`（健康に関わる情報を含むので、保存場所は限定する）

## 7. 運用のルール（スタッフ向け）

| こんなとき | やること |
|---|---|
| 新しく始める方 | 「＋ 新しく登録」→ 一緒にトレッドミルで測った速さを入れる → 出たマイコードをその場で一緒に入れる（画面を閉じるとコードは二度と出ない） |
| コードを忘れた・スマホを替えた | 「そのほかの操作」→「マイコードを作り直す」。前のコードとログイン中のスマホは使えなくなる |
| 体調の確認が出た | 様子を聞き、問題なければ「体調を確認した」を押す（押すまで次のメニューは出ない） |
| 退会・休会 | 「利用終了にする」。記録は残り、あとで「利用を再開する」で戻せる |
| ご本人から削除の申し出 | 「記録をすべて削除する」→ お名前を入れて確認。**元に戻せない**。スタッフの操作記録（誰が削除したか）だけ残る |
| プラン変更 | hacomono で変更したうえで、「名前・プラン・目標を直す」で合わせる |
| 合言葉を変える | 担当者が `npx wrangler pages secret put STAFF_PASSWORD` で再設定（スタッフが辞めたときは必ず変える）。設定のあと `npm run deploy` で公開し直すと、全員のスタッフ画面のログインが切れる |
